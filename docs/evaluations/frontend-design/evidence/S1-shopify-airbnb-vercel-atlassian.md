# S1: Shopify / Airbnb / Vercel / Atlassian - AI agents in design-system and front-end workflows
Researched 2026-10-17. P = primary (company-authored), T = third-party/secondary. Items I did not open directly are flagged.

## Atlassian (richest public material, all P)
- Structured content: schemas (TypeScript files kept beside code) for components, icons, tokens, lint rules, foundations; each covers usage, examples, props, content standards, a11y. AI "skills" auto-update this content and run evals and code-health checks. Claimed: 4.9% more accurate code, 11% fewer errors, 34% faster, 16% fewer tokens, 26% fewer tool calls, 52% accuracy on queries (own benchmarks). https://www.atlassian.com/blog/ai-at-work/teaching-ai-to-speak-our-design-language (2026-06-02); https://www.atlassian.com/blog/ai-at-work/atlassian-design-system-building-the-context-engine-for-the-ai-era
- ADS MCP (remote https://mcp.atlassian.com/v1/ads/public/mcp, local `npx -y @atlaskit/ads-mcp`): tokens, icons, components, primitives, a11y guidance. Also https://atlassian.design/llms.txt.
- Figma MCP + ADS MCP + Rovo Dev CLI redesign demo (2026-02-23): reads Figma and codebase conventions, plans, generates, runs tests, axe-core a11y fixes, humans review. Claims 4-5 dev-days -> 20 min, 1,381 LOC; self-caveated as depending on design-system maturity. https://www.atlassian.com/blog/development/redesigning-homepage-20-minutes-with-rovo-dev
- CLI (`npx @atlaskit/ads-cli search button`) 2026-09-16: same content for any shell/CI/agent; 8% faster, 8% fewer tokens vs MCP; benchmarked on real front-end tasks with transcript analysis (not just pass/fail). https://www.atlassian.com/blog/ai-at-work/giving-ai-agents-design-system-context-from-the-terminal-what-we-learned-building-a-cli
- DESIGN.md test (2026-06-15): token frontmatter + prose. On a login-screen task DESIGN.md used ~7.21M tokens vs 3.75M (MCP), 4.43M (skill), 4.20M (no context). Limits: all-at-once context, lossy compression (2.5 MB -> 80 KB), agents recreate components instead of importing. Recommended only for art direction, quick prototyping, customer theming, tool interop. Authors say not conclusive. https://www.atlassian.com/blog/how-we-build/atlassians-design-md-is-here-what-we-learned-testing-portable-design-context-in-practice ; file at atlassian.design/DESIGN.md
- Verification: lint rules in schema, axe-core, tests, human review, internal evals. No visual-regression detail found. Exploration vs production: DESIGN.md/Figma Make for exploration, MCP/CLI + real components for production (my inference from the DESIGN.md post).

## Vercel (rich, P)
- "Teaching agents product design at Vercel" (2026-06-25, John Phamous): `product-design` skill in-repo. Root AGENTS.md says when to load; skill-local AGENTS.md sets load order/validation. References: product-judgment, interface-quality, resilience, copy, patterns, surfaces-{surface}.md; exemplars (PRs worth repeating and mistakes); `coverage-gaps.md` listing where no standard exists; deterministic linters (no nested modals, accessible names on icon buttons); evals with before/after fixtures and hidden expected edits to test generalization to unseen UI. SKILL.md resolves a mode first: shape (compare alternatives, no edits), implement (smallest coherent change), review (findings, no edits unless asked), copy, harden (fix state/resilience/a11y, keep direction). Contract: "never claim visual verification from code alone." Findings P0-P3 with source and fix. Decision authority order: user goals > verified evidence > repo guidance > accepted decisions > adjacent patterns > heuristics. Weekly feedback collection from Slack/Figma/GitHub; candidates stay pending until a human accepts; never promote one screenshot or comment into a universal rule. https://vercel.com/blog/teaching-agents-product-design-at-vercel
- design.md (2026-08-31): public brand guidance file plus vercel-brand.css primitives loaded by agents (v0, Codex, Claude); includes anti-patterns ("generated-design patterns we never want"). 7 fixed scenarios, 200+ dev runs, 39 vs 91 known failures (57% fewer) on a self-described far too small sample; Slack @design-agent captures real use. https://vercel.com/blog/how-our-agents-build-on-brand-pages-with-design-md
- v0 Design Systems 2.0 docs: ingest GitHub, npm, Storybook/docs, Figma, screenshots, ZIPs; produces a "skill" with `v0.json` (max 3 reference sources, starter app, distilled instructions). v0 builds and previews a starter app and the user must approve before saving; updates re-validate. https://v0.app/docs/design-systems-2 . Launch date per T sources conflicts (Feb 5 vs June 25 2026); I did not find a Vercel blog post. Earlier (P): shadcn registry + MCP, 2025-08-22 https://vercel.com/blog/ai-powered-prototyping-with-design-systems ; Figma/npm import 2025-01-27 https://vercel.com/blog/working-with-figma-and-custom-design-systems-in-v0
- Not found: a first-party "design engineer" role essay or Geist-for-agents material beyond design.md (searched, nothing confirmed).

## Patterns relevant to a spec->plan->implement->gate pipeline
1. Mode routing up front (Vercel shape/implement/review/copy/harden): exploration modes explicitly forbid edits; harden preserves direction.
2. Design intent as in-repo routed references + exemplars + coverage-gaps, not one big file; Atlassian measured that a monolithic DESIGN.md loses to on-demand MCP/CLI lookups and causes component recreation. Use DESIGN.md only for art direction/prototyping.
3. Rules become deterministic lint where possible; rest as evals with hidden expected edits.
4. Rule promotion requires human acceptance and multiple sources (Vercel).
5. "Never claim visual verification from code alone" - render and inspect; Atlassian adds axe-core.
6. v0 starter-app preview-and-approve step gates design-system ingestion.
7. Evidence is mostly self-reported benchmarks with small samples (both Vercel and Atlassian say so).
