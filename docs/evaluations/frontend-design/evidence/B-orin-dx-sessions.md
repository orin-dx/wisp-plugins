## 7. Gaps (inference, grounded as noted)
1. No exploration/prototype mode: no skill for "sketch N variants, render, compare, pick" - user did it with artifacts, scratch pages, Playwright. The plugins start at requirement@1; there is no visual-options stage.
2. Muse spec has no visual-intent channel (tokens/measurements/reference screenshot as criteria are text; "visual balance over exact balance" cannot be a falsifiable criterion). Spec went stale on measurements (252px, 1180, 224x42, 44px).
3. No way to gate-on-render: gate checks spec text consistency, not rendered appearance; no screenshot/visual-diff stage. User plays that role ("That looks cheesy", "doesn't seem to follow the spec").
4. No promote/harden path from prototype to spec (spec-from-prototype, "freeze what we decided"); no decision log (user lost a width decision, #7883).
5. Gate has no severity/convergence control: wording-residue blockers keep a spec failing for 13 rounds; no "good enough for exploration" or max-scope-per-cycle enforcement (monolith SPEC-003 68 AC had to be split).
6. Large-spec ergonomics: 60-130 KB artifacts stall agents; drafters return inline JSON; orchestrator needed script-based slicing.
7. Supersession handling: no way to retire/obsolete specs when architecture changes (SPEC-001 vs SPEC-013) other than manual cleanup.
8. smith reviewer/exit-gate/mutator and sentinel unused: implementation verification relied on the orchestrator + `just check` + Playwright; unclear whether because of cost, stalls, or fit. UNKNOWN.
9. Hand-offs among agents were prose-heavy; orchestrator explicitly stated "The harness indents ... " noise; the plugin agent outputs were frequently delivered as hand-back messages with partial reports ("Its report wasn't delivered to me in full, so I'm checking the file on disk", #25564).
