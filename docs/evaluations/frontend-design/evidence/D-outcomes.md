## Why gates did not catch these
- Gates judge the spec on its own terms (internal consistency). Verdict blockers are about contradictions between ACs, missing states, wording ("AC-044 label role holds only for techworx"). That is valuable: SPEC-001 needed 13 verdict files, SPEC-005 retry_count 6, SPEC-002b hit the 3-retry escalation. But it found zero rendered-outcome defects; no step renders anything.
- Specs are testable-by-construction but over-specified at the wrong level: SPEC-013 has 39 ACs each of paragraph length with exact px, route-interception recipes and "Replaces SPEC-001 AC-056" chains; SPEC-001 had 120+ ACs. They read as CSS assertions (e.g. "logo capped 64px", "column gap 8px", duration before data-ready). The owner then decided on 12-13 Oct that visual/CSS-pin tests are not wanted: testing-prune-plan.md deleted 384 of 1116 tests (34%), including 28/33 in site-nav-css.test.ts, because they pinned values not behaviour. So a large share of what muse specs demanded (and smith/plan tasks implemented) was brittle CSS mirroring, then discarded. Meanwhile real visual risks (contrast, reflow, forced colours, target size) were parked in deferred-accessibility-tests.md and only rebuilt as one suite on 16 Oct (9dfe58e4, e9d921e9), which immediately found real failures.
- Spec/design thrash: SPEC-004..012 were gated pass on 11 Oct then "revised for design decisions" in one batch on 12 Oct (6fb08ba3, f8896db5, 1faebc1c). Visual decisions (focus ring side, brass depth, frosted ground, sheet corners) were made after gating via drawn pages (d72d7458, "ui-examples-open"). Muse specs encoded states and ARIA but not the owner's visual intent, which had to be discovered by looking.
- Gates passed first time (retry 0) for SPEC-006..012 on 11 Oct; they were produced in one day (8 specs). Suggests either good drafts or low adversarial pressure; each was immediately revised the next day for 5+ owner decisions.

## Verification infrastructure
- Exists: Vitest (~1100 tests before pruning, AC-id references in ~100 test files, e.g. apps/site-e2e/e2e/nav-sheet.spec.ts), nav-fixture Playwright suite (296 passing; Firefox absent), site-e2e (19 spec files, real built sites), Storybook (apps/storybook/stories; "about one line per component", SiteNav no story at 3 Oct), axe in six Vitest files and the 16 Oct audit.
- Tied to spec criteria: nav/chapter/breadcrumb specs reference AC ids; the later strands/landing work (SPEC-014..016) has none; the 16 Oct audit is tied to WCAG success criteria, not spec ACs.
- Gaps: Playwright suites are `runInCI: false` / "manual; not part of ci" (justfile lines 60-66; review-2026-10-11 headline 5; review-2026-10-03 testing gaps). Zero toHaveScreenshot / no screenshot regression (grep: 0), no Storybook build/visual in CI, no JS size budget (271 KB hydrated), packages/rules is a README only (SPEC-002 rules checker never ported). The enforcement that review 11 Oct says is missing is exactly the layer that would have caught NaN, calc() breakage, hex/px/!important.
- Owner policy 13 Oct: "we test behaviour, visual testing comes later" - correct for brittleness, but nothing replaced it until 16 Oct.

## Spec-code drift, duplicates, competing abstractions
- Drift: SPEC-001/003a/003c vs shipped (above); decisions-status.md (13 Oct) opens "after two decisions turned out to be recorded but not applied". design-system-coverage lists MenuSheet "removed; NavSheet built" while review 11 Oct still describes MenuSheet; docs go stale within a day (commits "Correct stale thresholds ... in the docs", 8cebb61b "four stale tests").
- Duplicates (review 11 Oct, still visible): packages/orin and packages/twx both have button, button-link, code-block, command-line, hero, icon, margin-note, view-toggle. packages/foundations/src/ui AND packages/components/src both carry button, button-link, field, sheet-ish components (23 app files import foundations/ui). Five theme-toggle copies were the stated target. 40 files in apps/orin-dx and techworx still call css() (policy: recipes only). Brand branching (13 `brand === ...`) inside shared code.
- Spec numbering collisions in practice: SPEC-002/002a/b/c split, SPEC-003/a/b/c, PLAN-003 vs PLAN-004 superseded; "Replaces SPEC-001 AC-xxx" chains make the live contract hard to read.

## Overall judgement
Plugin work reliably produced consistent, testable, well-challenged spec text and plans for interaction/ARIA/geometry of components (nav, rails, base layer). It did not produce good visual outcomes by itself: every visible-quality defect above (NaN, broken masks, stretched marks, phone openers, contrast/targets, landmarks, copy truth) was found by a human look, a post-hoc audit or a new test suite, and the best-defended area (nav) is also where the owner deleted the most tests as too brittle. The late, strong results came from two ad hoc moves: a whole-site crawl/axe/target-size/reflow audit (16 Oct) and independent fact-check/review docs. The missing pipeline stage is a rendered-outcome check (screenshots at 320/375/760/1440 in both themes and brands, contrast/target/reflow probe, copy-vs-source check) run in CI and referenced from spec criteria.
